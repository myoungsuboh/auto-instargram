# ADR-0009: 인스타그램 토큰 교환은 재시도하지 않는다

- 기록일: 2026-07-29 12:32
- 상태: 승인됨
- 단계(Origin): dev (execute-dev)
- 관련 spec: [1_spack.md — API-05](../../1_spack.md), [3_architecture.md — SVC-02 외부 의존성](../../3_architecture.md)
- 관련 plan: [00-ORCHESTRATOR.md — Phase 2 Task 2.1](../../00-ORCHESTRATOR.md)

## 맥락 (Context)

[skills/core/error-handling-error-handling-resilience.md](../../skills/core/error-handling-error-handling-resilience.md)
규칙 3 은 "일시적 실패는 지수 백오프 + 지터 + 상한과 함께 재시도"를 요구한다.
API-05 는 Meta Instagram Graph API 를 호출하므로 일반적으로는 재시도 대상이다.

그런데 같은 문서 규칙 4 가 단서를 붙인다: "**재시도하려면 멱등성이 필요하다**".
단기→장기 토큰 교환은 멱등이 아니다 — 교환이 서버에서 성공했는데 응답만 유실된 경우,
재시도하면 이미 소비된 단기 토큰으로 다시 요청하게 되고 발급된 장기 토큰을 영구히 잃는다.

## 결정 (Decision)

토큰 교환은 한 번만 시도하고, 실패는 재시도 없이 사용자에게 정확한 코드로 알린다(422/502).

## 고려한 대안 (Alternatives)

| 대안 | 장점 | 단점 | 채택 여부 |
|------|------|------|-----------|
| 재시도 없음 + 명확한 에러 | 발급된 장기 토큰을 잃을 위험이 없다. POL-04(3초) 예산 안에 확실히 들어온다 | 일시적 네트워크 오류에도 사용자가 직접 다시 눌러야 한다 | **채택** |
| 백오프 재시도 2~3회 | 일시적 오류를 자동 흡수 | 비멱등 연산이라 "성공했는데 응답 유실" 시 토큰 손실. 최악의 경우 3초를 넘겨 POL-04 위반 | 기각 |
| 멱등 키를 붙여 재시도 | 안전한 재시도가 가능 | 멱등 키는 우리 서버가 아니라 **Meta 쪽**이 지원해야 한다. 외부 API 계약을 우리가 바꿀 수 없음 | 기각(불가능) |

## 근거 (Rationale)

규칙 3(재시도하라)과 규칙 4(멱등해야 재시도하라)가 충돌할 때 규칙 4 가 이긴다 —
규칙 4 는 규칙 3 의 전제조건이기 때문이다.
"자동 복구를 시도했다가 사용자의 장기 토큰을 잃는 것"보다
"사용자가 버튼을 한 번 더 누르는 것"이 압도적으로 낫다.

타임아웃은 반드시 둔다(연결 800ms + 응답 1700ms = 최대 2.5초) —
재시도를 안 하는 것과 무한 대기하는 것은 다른 문제다(공통 규칙: 외부 호출엔 타임아웃 필수).

## 영향 (Consequences)

- 긍정: 토큰 손실 위험 없음. 외부 호출이 느려도 POL-04(3초) 안에 응답이 끝난다.
  외부 실패는 502 `UPSTREAM_UNAVAILABLE` 로 우리 버그(5xx)와 구분해 알린다.
- 트레이드오프/비용: 일시적 오류가 사용자에게 그대로 노출된다. 화면에 "다시 시도" 안내가 필요하다(Phase 4).
- 후속 제약:
  - **이 호출에 재시도 로직을 추가하지 말 것.** 추가하려면 Meta 가 멱등 키를 지원하는지 먼저 확인해야 한다.
  - 안전하게 재시도할 수 있는 경로(만료 임박 토큰의 백그라운드 자동 갱신)는 이번 설계 범위에 없다.
    도입한다면 그때는 재시도가 정당해질 수 있으므로 이 ADR 을 재검토한다.
