# ADR-0018: 미디어 해시는 파일을 읽을 수 없으면 경로 기준으로 대체한다

- 기록일: 2026-07-29 14:34
- 상태: 승인됨
- 단계(Origin): dev (execute-dev)
- 관련 spec: [1_spack.md — ENT-01 / POL-01](../../1_spack.md), [2_ddd.md — AGG-01](../../2_ddd.md)
- 관련 결정: [ADR-0014](2026-07-29-publish-attempts-audit-table.md)

## 맥락 (Context)

두 제약이 맞물린다:

- `history_records.content_hash` 는 **NOT NULL** 이고 정확히 64자여야 한다
  (ENT-01: "SHA-256 중복 방지 해시", AGG-01 불변식 1).
- **POL-01** — "모든 실패 경로는 누락 없이 로그 및 이력에 기록되어야 함".

즉 <b>실패를 기록하려면 반드시 해시가 있어야 한다.</b>
그런데 실패의 흔한 원인이 바로 "파일을 읽을 수 없음"이다(파일이 지워졌거나, 권한이 없거나, 경로가 잘못됨).
그 경우 콘텐츠 해시를 계산할 수 없고, 해시가 없으면 이력을 남길 수 없어 POL-01 을 위반한다.

## 결정 (Decision)

파일 콘텐츠 해시를 우선 시도하고, 읽을 수 없으면 **경로 문자열의 SHA-256** 으로 대체한다.
대체가 일어났다는 사실을 로그로 남긴다.

## 고려한 대안 (Alternatives)

| 대안 | 장점 | 단점 | 채택 여부 |
|------|------|------|-----------|
| 경로 해시로 대체 + 로그 | POL-01 을 지킬 수 있다(실패를 반드시 기록). 형식(64자 hex)이 동일해 제약을 만족 | 그 레코드의 중복 방지가 콘텐츠 기준이 아니라 경로 기준으로 동작한다 | **채택** |
| 해시 없으면 이력을 남기지 않는다 | 해시의 의미가 항상 "콘텐츠"로 일관됨 | **POL-01 정면 위반** — 가장 흔한 실패 유형이 기록되지 않는다. "파일이 없어서 실패했다"는 사실을 조사할 수 없다 | 기각 |
| `content_hash` 를 nullable 로 변경 | 의미가 명확해진다(모르면 NULL) | AGG-01 불변식 1(해시는 미디어별 유일)의 근거가 흔들린다. NULL 이 여러 개면 유니크 인덱스가 무의미해지고, 조회 코드가 NULL 분기를 곳곳에 갖게 된다 | 기각 |
| 고정 더미 해시(예: 0×64) 사용 | 단순함 | 파일을 읽지 못한 모든 실패가 <b>하나의 행</b>을 공유해 서로를 덮어쓴다 — POL-01 을 더 크게 위반한다 | 기각 |

## 근거 (Rationale)

"실패를 기록조차 못 하는 것"보다 "경로 기준으로라도 기록하는 것"이 낫다고 판단했다.
POL-01 은 이 시스템의 감사 요구사항이고, 기록되지 않은 실패는 조사할 수 없다.

경로 해시를 고른 이유는 **결정적(deterministic)이면서 서로 구별된다**는 점이다 —
고정 더미 해시는 모든 실패가 한 행에 뭉개지지만, 경로 해시는 파일마다 다른 행이 된다.

[ADR-0014](2026-07-29-publish-attempts-audit-table.md) 의 `publish_attempts` 가 이 절충의 피해를 줄인다 —
해시가 겹치더라도 시도 기록은 append-only 로 모두 남는다.

## 영향 (Consequences)

- 긍정: 파일을 읽을 수 없는 실패도 이력과 감사 기록에 남는다(POL-01 충족).
  대체가 일어났다는 사실이 로그에 남아 조사 시 구분 가능하다.
- 트레이드오프/비용:
  - **같은 미디어가 두 개의 해시를 가질 수 있다.** 파일을 읽지 못했을 때(경로 해시)와
    나중에 읽을 수 있게 됐을 때(콘텐츠 해시)가 다르므로, 같은 영상에 이력 행이 두 개 생긴다.
    그 경우 중복 업로드 방지가 한쪽을 놓친다.
  - 서로 다른 파일이 같은 경로에 놓였다가 교체되면(파일 덮어쓰기) 경로 해시는 같다.
- 후속 제약:
  - 이 대체 동작을 제거하려면 먼저 POL-01 을 다른 방법으로 만족시켜야 한다
    (예: `content_hash` nullable 화 + 유니크 조건 재설계).
  - 대체 발생 로그를 지우면 "콘텐츠 기준인지 경로 기준인지" 구분이 불가능해진다.
