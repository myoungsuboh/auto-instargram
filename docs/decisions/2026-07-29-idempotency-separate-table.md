# ADR-0016: 멱등성은 전용 테이블로 구현한다

- 기록일: 2026-07-29 14:31
- 상태: 승인됨
- 단계(Origin): dev (execute-dev)
- 관련 spec: [1_spack.md — API-01 / API-04](../../1_spack.md)
- 관련 plan: [00-ORCHESTRATOR.md — Phase 3 Task 3.1](../../00-ORCHESTRATOR.md)
- 적용 스킬: [skills/backEnd/idempotency-idempotency.md](../../skills/backEnd/idempotency-idempotency.md)

## 맥락 (Context)

Task 3.1 은 "Ensure idempotency for queue registration" 을 요구하고,
`skills/backEnd/idempotency-idempotency.md` 가 구체적 요구사항을 정한다:

- 규칙 1 — 부작용 있는 POST 는 `Idempotency-Key` 헤더 지원
- 규칙 2 — 첫 요청 **결과를 저장**하고 재요청 시 **저장된 결과를 반환**
- 규칙 3 — 키는 클라이언트가 만든 UUID v4, **TTL 24시간 이상**
- 규칙 4 — 처리 중인 요청의 중복 도달은 **409 Conflict**

Phase 1 의 `_workspace/db_schema.json` 은 "queue_items 에 멱등성 키 컬럼 추가"로 계획해 두었으나,
위 요구사항을 다시 읽으면 컬럼 하나로는 담을 수 없다.

## 결정 (Decision)

`idempotency_records` 전용 테이블을 만든다 (V3 마이그레이션).
키·엔드포인트·요청 지문·상태·응답 본문·만료 시각을 갖는다.

## 고려한 대안 (Alternatives)

| 대안 | 장점 | 단점 | 채택 여부 |
|------|------|------|-----------|
| 전용 테이블 | 규칙 2(응답 보관)·3(TTL)·4(처리 중 상태)를 모두 담을 수 있다. 여러 엔드포인트가 재사용한다(API-01·API-04) | 테이블 1개 추가 | **채택** |
| `queue_items` 에 컬럼 추가 (원래 계획) | 테이블 추가 없음 | ① 응답 본문을 보관할 자리가 없다(규칙 2 불가) ② TTL 을 도메인 테이블에 섞으면 예약 데이터가 만료 대상이 된다 ③ 다른 엔드포인트가 재사용할 수 없다 | 기각 |
| Redis 에 보관 | 만료가 자동, 빠름 | 3_architecture.md 에 Redis 가 없다 — 아키텍처에 없는 구성요소 발명. 재시작 시 유실되면 중복 방지가 뚫린다 | 기각 |
| 멱등성 미구현 | 가장 간단 | Task 3.1 이 명시적으로 요구한다. 게시는 되돌릴 수 없어(비멱등) 중복 요청이 실제 피해를 만든다 | 기각 |

## 근거 (Rationale)

규칙 2 가 "저장된 **결과를** 반환"하라고 요구하는 순간 컬럼 방식은 불가능해진다 —
응답 JSON 을 어딘가에 보관해야 하고, 그것은 도메인 테이블의 책임이 아니다.
규칙 3 의 TTL 도 도메인 데이터와 수명 주기가 완전히 다르다.

동시 요청 처리는 애플리케이션 락 없이 **DB 유니크 인덱스**로 해결했다 —
두 요청이 같은 키로 동시에 INSERT 하면 늦은 쪽이 제약 위반으로 실패하고,
그것을 그대로 409(규칙 4)로 변환한다. 락을 도입하지 않고 정확성을 얻는다.

`REQUIRES_NEW` 트랜잭션으로 시작 표시를 **즉시 커밋**하는 것이 핵심이다 —
커밋되지 않으면 동시에 들어온 두 번째 요청이 그것을 볼 수 없어 중복 감지가 무력화된다.

실패 시 표시를 **해제**하는 것도 의도된 설계다. 해제하지 않으면 그 키는 TTL(48시간) 동안
계속 409 를 돌려주어 정상적인 재시도조차 불가능해진다.
보호해야 하는 것은 "성공한 부작용이 두 번 일어나는 것"이고, 실패는 보호 대상이 아니다.

## 영향 (Consequences)

- 긍정: 실측 확인 — 같은 키·같은 내용은 첫 응답을 그대로 재생(같은 queueId),
  같은 키·다른 내용은 422 로 거부, UUID v4 가 아닌 키는 422 로 거부, 실패 후 같은 키로 재시도 가능.
  API-01·API-04 가 같은 장치를 공유한다.
- 트레이드오프/비용:
  - 헤더가 **선택 항목**이다(명세가 필수로 규정하지 않았다). 헤더 없이 보내면 멱등 보호가 없다 —
    화면(Phase 4)은 항상 헤더를 보내야 한다.
  - 테이블이 쌓인다. TTL 이 지난 행은 논리 삭제되지만 정리 배치는 범위 밖(정책만 문서화).
- 후속 제약:
  - **`beginOrReplay` 의 `REQUIRES_NEW` 를 제거하면 동시 중복 감지가 조용히 깨진다.**
  - 실패 시 `release` 를 호출하지 않으면 그 키가 48시간 동안 잠긴다.
  - 요청 지문(본문 SHA-256)이 없으면 같은 키로 다른 내용을 보낸 요청에 첫 응답을 돌려주게 된다.
